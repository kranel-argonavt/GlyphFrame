## Reproduction

```powershell
dotnet build GlyphFrame.sln -c Release --no-restore
dotnet test GlyphFrame.sln -c Release --no-build --no-restore --filter "FullyQualifiedName~ManagedRender_RealUnicodeContainer|FullyQualifiedName~ResolutionWarning_|FullyQualifiedName~PackageVerificationDataRootTests"
dotnet test GlyphFrame.sln -c Release --no-build --no-restore
dotnet format GlyphFrame.sln --verify-no-changes --no-restore
git diff --check
pwsh -NoProfile -File scripts/Test-PackageVerificationSession.ps1
pwsh -NoProfile -File scripts/Verify-PublishPackage.ps1
```

The script requires Windows, PowerShell 7, the .NET 10 SDK, and access to the configured NuGet sources/runtime packs. It publishes the actual `src/GlyphFrame.App/GlyphFrame.App.csproj`, not a test host. Each invocation creates a unique ignored `artifacts/package-verification/<id>/` containing the package, version output, and `report.json`. Application data instead uses a short, unique `%TEMP%\GFpkg\<id>` directory. The marked data directory is retained for failure inspection and interactive retesting; it is not a distributable part of the package. The verifier removes only its validated empty outside-repository working directory, and only after session cleanup was verified; on failure that working directory is retained too. Verify session removal before any later deletion of the exact run-owned data root. No publish is performed by normal xUnit runs; no system PATH/software/settings are changed. Existing `.gitignore` already excludes `artifacts/`, so packages and diagnostics stay out of Git.

Before creating application data or launching, the same regression-tested helper budgets prospective production completed and `.pending.mp4` paths, including their escaped absolute file URIs. It uses the production session/artifact naming patterns and the longest positive Int32 PID, allowing **220 characters per filesystem path and 240 per URI**. An unsuitable temporary base fails explicitly; there is no deeply nested artifacts-directory fallback. This is a conservative **test-harness safeguard**, not a universal Windows limit or a product restriction. `report.json` records the root, both budgets and lengths, actual observed-session naming lengths, and an exact `InteractiveLaunchCommand` for the fresh package using the same short root.

For verification only, the app accepts `--verification-data-root <absolute-directory>` when that directory contains `.glyphframe-package-verification`. The script supplies its own marked directory; ordinary launches retain `%LocalAppData%\GlyphFrame`. The real user-local root and GlyphFrame profile are rejected as verification roots. This explicit path seam isolates settings, logs, and managed cache instead of relying on environment-variable redirection of Windows known folders. Do not use this switch for normal application launches.

The verifier checks the self-contained runtime configuration, application executable/assemblies, CLR/WPF native runtime, SkiaSharp native asset, FFmpeg/ffprobe, checksum manifest, GPL license, distribution information, and third-party notices. The archive checksum remains provenance; the archive itself is not required in the package. Every shipped FFmpeg manifest entry is checked against the committed manifest. Both tools execute using application-relative paths from the outside working directory. OpenCV/OpenCvSharp assets cause failure. App startup must create a responsive main window and survive the observation interval.

Isolation then requires **positive evidence** within a further bounded 15-second poll: exactly one canonical `session-<launched-PID>-<GUID>` directory below this run's `%TEMP%/GFpkg/<id>/GlyphFrame/Cache/VideoArtifacts`, with the production `.session.lease` file actively held. The read-only helper opens that existing file with `FileMode.Open`, `FileAccess.ReadWrite`, and `FileShare.None`, matching production probing semantics. Only `ERROR_SHARING_VIOLATION` (`0x80070020`) from that competing open counts as an active lease. Missing/unlocked files, access denial, byte-range lock errors, and arbitrary I/O failures do not count; unsafe/reparse-point cache boundaries are rejected. The verifier never creates the session or lease. Missing or empty caches time out and fail even if the app is responsive.

Graceful shutdown must finish within 15 seconds with exit code zero. Cleanup is a distinct check: the **observed** session path must be gone and an accessible, safe isolated cache must contain zero remaining directories. Missing/inaccessible cache state cannot silently pass. `report.json` retains separate `SessionObservation` (cache/session/lease paths, launched PID, UTC observation, specific lock evidence) and `SessionCleanup` (observed removal, remaining directories, success) objects; a failure before either check leaves that evidence absent, not successful. Failure cleanup still targets only the process started by this invocation, with bounded termination as a last resort. Package/evidence remain ignored for inspection.
