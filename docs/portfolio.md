# Publication preparation

## Publication scope

The [public GlyphFrame repository](https://github.com/kranel-argonavt/GlyphFrame) retains the reviewed development history. The remaining target is **separate ready-to-run downloads through GitHub Releases**, not a new root commit, a shallow public history or a permanent source-only distribution. The private original and recovery materials remain separate from this published copy.

| Publication channel | Intended contents |
| --- | --- |
| Git repository and reviewed history | Original application code, tests/synthetic fixtures, project-owned assets, maintained docs, build/installer scripts, MIT and third-party notices; preserve legitimate development commits, messages and authorship |
| GitHub Release assets | Self-contained Setup and portable ZIP bundling the controlled tools/runtime, plus exact FFmpeg tool/source-build materials, complete notices and checksums through the reviewed delivery route |

Generated EXEs, archives, restored packages, caches, personal settings, unrelated media and private journals do not belong in Git. Release assets are not committed blobs, and a draft/provisional file is not automatically approved for upload. End users should launch the installed/extracted application without separately installing .NET or FFmpeg; explicit pinned tool preparation is a developer build step.

The root [README](../README.md) explains source builds; [licensing](licensing.md) records the separate repository and binary-release scopes. The published gallery uses project branding, a startup-screen hero, an AI-generated car comparison and a linked symbolized video; additional screenshots are collapsed. [Media notes](screenshots/README.md) identify the owner-provided Pixabay source and record the owner's completed review and decision on 2026-10-29 to retain this specific GlyphFrame-symbolized result, without distributing the original clip. The demo was retained in the published history. This owner assessment is not independent legal clearance or approval of the bundled release packages.

## Remaining release sequence

Use the existing [Releases channel](https://github.com/kranel-argonavt/GlyphFrame/releases). A release tag and its asset URLs have not been selected or created; the repository URL alone is not a binary/source download. The current published snapshot is the starting point for preparation, not the identity of an already built release package.

1. **Close the material review.** Record the selected source/guide/runtime-scope treatment and Windows-component coverage against the existing exact inputs. Keep the owner-adopted terms, controlled tool pins and frozen source ZIP unchanged unless a concrete new finding requires a separately reviewed change. Do not collect the unselected runtime-source supplement by default.
2. **Checkpoint the release preparation.** Select the actual application commit/version and intended versioned release tag. Use the explicit [ReleasePrepared path](packaging.md#explicit-release-preparation), which checks the definition, clean source and matching delivery archive; keep provisional defaults and do not bypass review by flipping approval flags.
3. **Build and bind fresh candidates.** Use a clean checkout of that commit for Setup and portable, record `WorkingTreeDirty=false`, tool/runtime identities, payload hashes and automated results. Older private or filtered-baseline packages are not substitutes for these new bytes.
4. **Retest the affected packages.** Check first-use terms/refusal, retained acceptance and restart, image/video render/export, offline notices and the affected Setup lifecycle. Carry forward unaffected older manual evidence with its original package identity; repeat only what the new bytes or remaining gaps require.
5. **Approve and publish the matching set.** Review release notes, version-specific links and checksums, then obtain explicit owner approval. Draft asset links are not proof of anonymous access: verify the real matching source download before exposing binary downloads, and verify all final downloaded bytes. Keep matching source available with the binaries.

| Final checksums and release notes | Cover the actual uploaded files, source/tool mapping, Windows x64 deployment, unsigned-Setup status and real source links; exclude private reports, settings and backups |

## Available fallback: export current source without history

The existing snapshot workflow is **not selected for publication**. It remains a backup/inspection option and could become a publication alternative only after an explicit owner decision to abandon the chosen history-preserving route. Do not use its history-free output as the agreed public repository. From the private development repository, after reviewing current changes:

```powershell
pwsh -NoProfile -File scripts/Export-PortfolioSource.ps1
```

The script creates a fresh ignored `artifacts/portfolio-source/<run-id>/GlyphFrame/` containing current tracked/nonignored source files, including uncommitted edits, but no `.git`. It rejects unexpected root paths, executables, archives, generated/private directories, linked files and unreviewed media locations. It verifies every copied SHA-256 and rechecks source/status stability. Only the two deliberately removed tracked tool EXEs may be absent. Unknown/missing content fails rather than being silently omitted.

Sibling `source-manifest.json` and `report.json` are local evidence, **not part of the public source folder**. They record the parent revision and dirty state; a snapshot is not a clean commit, Git clone or binary release. This is a conservative path policy, not a complete content/secret scanner. Review text, asset rights, links and the manifest before publication.
