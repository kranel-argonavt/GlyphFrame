# GlyphFrame {{VERSION}} — Windows x64 portable application

Extract the **entire ZIP** before launching. Open `GlyphFrame.App.exe` inside the extracted application directory. Keep all bundled files and the `Tools/ffmpeg/` structure together; do not run directly inside the ZIP or move only the EXE.

The folder contains a self-contained .NET/WPF runtime, Skia dependencies, FFmpeg and ffprobe; a separate .NET runtime or FFmpeg installation is not required by the deployment design. Compatibility still depends on the Windows environment and media components. Build-specific verification and manual-test scope are recorded in the repository's acceptance documentation; this README is not a guarantee for every Windows installation.

Portable means **deployment without an installer**, not beside-EXE application data. Normal settings, privacy-safe logs and managed review cache remain under `%LocalAppData%\GlyphFrame`. Media stays local; no telemetry or upload is added. `--verification-data-root` is a marked, explicit test-only opt-in, not normal usage.

This local candidate uses **Microsoft component terms, version 1.0**, adopted for five identified bundled Microsoft components only. On a fresh self-contained scope, review the complete terms and local references before media work. The agreement choice starts unchecked; Decline, Escape or closing exits. The separate `native-terms-acknowledgement.txt` convenience record is independent of Settings and applies only to the exact current scope, not authenticated legal proof. Older nonoperative preview records do not satisfy it. Missing/altered documents or covered runtime files block startup; restore the complete matching package. This provisional candidate is not an approved public release.

To remove the application, close it and delete its extracted directory. That does not remove user-local preferences/logs or exports saved elsewhere. Do not delete another running instance's cache. No PATH or Windows installation changes are required by this package.

Target platform: Windows 10/11, x64. Original playback depends on Windows media components/codecs; import or FFmpeg decoding support does not guarantee continuous WPF playback. Unsupported playback retains frame-preview/rendering fallback. Long media/cache paths can limit WPF playback; use a reasonably short extraction path. Environment-specific results apply only to the tested Windows build, media and package; unusual codecs or other installations may behave differently.
